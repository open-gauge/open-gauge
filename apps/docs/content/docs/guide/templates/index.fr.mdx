Un **modèle de document** est une mise en page réutilisable pour un document imprimable — un
certificat de calibration ou une procédure de calibration — conçu une seule fois et rempli avec
des données réelles à chaque génération. Gérez-les depuis **Panneau d'Administration → Modèles**,
un groupe repliable dans la barre latérale d'administration avec deux panneaux : **Rapports de
Calibration** (les modèles de type certificat de cet éditeur, aux côtés des modèles LaTeX créés à
la main — voir [Modèles de certificat](../calibration/certificate-templates.mdx)) et
**Procédures**. Les deux panneaux partagent la même disposition et les mêmes actions — voir
[Gérer les modèles : base, par défaut et actif](#gérer-les-modèles-base-par-défaut-et-actif)
ci-dessous. Le bouton **« + Nouveau modèle »** de chaque panneau ouvre une fenêtre modale
(l'import LaTeX n'apparaît que sur le panneau Rapports de Calibration, les procédures n'ayant
aucun système LaTeX hérité) ; « Créer un nouveau modèle » est l'option qui ouvre cet éditeur pour
un modèle vierge. L'export/import et la génération sont décrits dans
[Génération de PDF](#génération-de-pdf) ci-dessous.

## Deux types de modèles

- **Certificat de Calibration** — expose des variables d'actif, de calibration, de mesures, de
  coefficients/statistiques, d'incertitude, de technicien, de laboratoire et de métadonnées de
  certificat.
- **Procédure de Calibration** — expose des variables d'équipement, de métadonnées de procédure,
  de conditions environnementales, d'étapes, de critères d'acceptation, de consignes de sécurité,
  de technicien, d'approbation et d'historique de révisions.

Seules les variables pertinentes pour le type du modèle sont affichées lors de son édition.

## Gérer les modèles : base, par défaut et actif

Chaque panneau (Rapports de Calibration, Procédures) liste tous les modèles de ce type sous forme
d'une ligne — les modèles LaTeX et ceux de l'éditeur partagent la même disposition de ligne —
avec trois concepts qui fonctionnent de façon identique dans les deux panneaux :

- **Base** — chaque type est livré avec une ligne permanente « Open Gauge (default) », toujours
  affichée en premier. Elle est créée automatiquement la première fois que vous ouvrez ce panneau
  (ou la première fois qu'un document de ce type est généré sans rien configuré) — rien à préparer
  sur une installation neuve. Elle ne peut être ni modifiée ni supprimée, mais son état
  **Par défaut**/**Actif** se change comme celui de n'importe quelle autre ligne.
- **Par défaut** — exactement un modèle actif par type est le modèle par défaut, utilisé chaque
  fois qu'un document est généré sans choix de modèle explicite (voir
  [Génération de PDF](#génération-de-pdf) et
  [Télécharger une procédure en PDF](../procedures/index.mdx#télécharger-une-procédure-en-pdf)).
  Cliquez sur la coche d'une autre ligne pour en faire le modèle par défaut — l'ancien est
  désélectionné automatiquement. Si aucun modèle n'est jamais marqué par défaut, c'est le modèle
  de base qui l'est. Sur le panneau Rapports de Calibration, il s'agit d'un *unique* modèle par
  défaut partagé entre les modèles LaTeX et ceux de l'éditeur — marquer un modèle de l'éditeur par
  défaut désélectionne un modèle LaTeX, et inversement.
- **Actif** — chaque modèle a aussi un interrupteur Actif, indépendant de Par défaut. Désactiver
  un modèle le retire du sélecteur de téléchargement (il ne peut plus être choisi, ni par défaut
  ni explicitement) tout en restant exactement à sa place dans la liste — toujours visible,
  modifiable, facile à réactiver. C'est différent de **Supprimer**, qui retire complètement un
  modèle de la liste. Le modèle de base ne peut pas être désactivé tant qu'il est le modèle par
  défaut actuel (il n'y aurait plus rien vers quoi se replier) — marquez d'abord un autre modèle
  par défaut. Désactiver (ou supprimer) le modèle par défaut actuel bascule automatiquement vers
  le modèle de base.

## La disposition de l'éditeur

L'éditeur est une disposition de bureau à trois panneaux, pas une page web défilante — le panneau
central affiche le document comme une page physique A4 (ou Lettre), dans les mêmes proportions
que celles avec lesquelles il sera finalement imprimé.

- **Outils** (gauche) — cliquez ou glissez un élément sur la page pour l'insérer : texte (titre,
  paragraphe, ligne horizontale, saut de page), données (variable, tableau, tableau de mesures,
  champ clé/valeur), technique (équation, graphique, tracé des données de calibration, image,
  code QR, signature, date, numéro de page) et mise en page (colonnes, espaceur, section, en-tête,
  pied de page).
- **Toile de la page** (centre) — cliquez sur n'importe quel texte pour le modifier sur place ;
  une barre d'outils de formatage contextuelle (police, taille, gras/italique/souligné,
  alignement, couleur, surlignage, interligne/espacement des paragraphes, listes) apparaît
  au-dessus de la page lorsqu'un bloc de texte est sélectionné. Les propriétés structurées propres
  à un bloc (les lignes/colonnes d'un tableau, les axes d'un graphique, le contenu d'un code QR,
  …) se modifient depuis l'onglet **Bloc** à droite.
- **Variables** (droite) — recherchez ou parcourez chaque variable disponible pour le type du
  modèle, regroupées par catégorie (Actif, Calibration, Résultats de Calibration, Mesures,
  Organisation, Utilisateur/Technicien, Dates, …). Cliquer sur l'une l'insère dans le bloc de
  texte sélectionné, ou ajoute un nouveau paragraphe si rien n'est sélectionné. Une variable de
  collection (p. ex. Mesures) est affichée séparément des variables scalaires et peut être
  insérée sous forme de tableau répétitif prêt à l'emploi.

## Mode Modèle vs. Données d'aperçu

Basculez entre le mode **Modèle** — affichant les jetons `{{ variable }}` bruts — et le mode
**Données d'aperçu**, qui remplace chaque jeton par des valeurs d'exemple réalistes (p. ex.
`{{asset.id}}` → `OG-000123`) afin que vous puissiez voir approximativement à quoi ressemblera un
document généré avant même qu'une calibration réelle n'existe. Un tableau répétitif lié à une
variable de collection affiche une ligne d'exemple par point de données d'exemple en mode aperçu.

## Le modèle de document

Le contenu d'un modèle est stocké sous forme de JSON structuré — un tableau de **blocs** typés
(`heading`, `table`, `equation`, `qr_code`, …), chacun avec ses propres propriétés — jamais sous
forme de chaîne HTML. Cela garde le résultat de l'éditeur reproductible par un futur moteur de
rendu PDF côté serveur, qui parcourra le même arbre de blocs que celui dessiné par le navigateur
plutôt que d'essayer de réinterpréter du HTML/CSS arbitraire.

La mise en page (taille, orientation, marges, typographie par défaut) et l'en-tête/pied de page
répétitif sont des paramètres au niveau du document, modifiés depuis l'onglet **Document** à
droite — le contenu de l'en-tête et du pied de page se répète sur chaque page produite par un PDF
généré.

## Versionnage et publication

L'historique d'un modèle fonctionne comme l'historique de calibration : **immuable et
traçable**.

- Un nouveau modèle commence en tant que **version 1, brouillon** — modifiable, enregistré
  automatiquement au fur et à mesure.
- **Publier** fige cette version. Un modèle publié ne peut plus être modifié sur place — il a
  peut-être déjà été utilisé pour générer de véritables certificats.
- Modifier un modèle publié crée une nouvelle version **brouillon** (version + 1) dans le même
  groupe de modèle ; publier ce brouillon remplace le précédent. Si un brouillon existe déjà,
  modifier à nouveau rouvre ce même brouillon plutôt que d'en créer un autre.
- **Dupliquer** crée à la place un modèle entièrement nouveau et indépendant (avec son propre
  historique de versions) pré-rempli avec le contenu de la version source — pour démarrer une
  variante plutôt que de continuer la même.
- **Archiver** masque un modèle de la liste par défaut sans supprimer son historique.

## Images

Les images (un logo d'entreprise, une marque d'accréditation, un diagramme) sont téléversées par
modèle et stockées sous forme de références de fichiers — un bloc image contient un `file_id` et
une URL d'aperçu résolue, pas une copie intégrée des octets du fichier.

## Export et import

Un modèle peut être exporté vers un fichier JSON portable (son nom, sa description, son type et
son document complet) et réimporté ailleurs — comme un nouveau brouillon, avec son propre
historique de versions indépendant — via **« Nouveau modèle » → « Importer un modèle JSON »**.
Comme pour l'option d'import LaTeX, la fenêtre modale affiche un aperçu en direct du fichier
sélectionné et permet de remplacer le nom et le numéro de version de départ avant de créer le
brouillon. Contrairement à un téléversement `.tex` brut, un modèle exporté fait l'aller-retour
par ce même éditeur : importez-le, continuez à l'éditer, publiez-le. Ce n'est pas du LaTeX —
celui-ci est généré automatiquement au moment du PDF (voir ci-dessous), pas quelque chose que
vous rédigez ou échangez directement.

## Génération de PDF

Un modèle de l'éditeur **publié** peut générer un véritable PDF de rapport de calibration, de la
même manière qu'un modèle de certificat `.tex` téléversé. En interne, le document JSON structuré
du modèle est converti en LaTeX et compilé avec le même pipeline
[Tectonic](../calibration/certificate-templates.mdx) — pas de moteur PDF séparé, pas de règles
d'échappement séparées à apprendre. Les blocs équation stockent déjà du LaTeX brut, donc ils
passent directement ; tous les autres blocs (texte, tableaux, lignes répétitives liées à une
collection, graphiques, codes QR, colonnes, …) sont traduits automatiquement.

Un modèle de type **Procédure de Calibration** publié est généré de la même façon, mais pour une
[procédure](../procedures/index.mdx) plutôt qu'une calibration — voir [Télécharger une procédure en
PDF](../procedures/index.mdx#télécharger-une-procédure-en-pdf). Il n'y a pas de chaîne de
résolution par voie/organisation pour les procédures (une procédure n'est pas liée à une voie de
capteur comme l'est un rapport de calibration) : le bouton **Télécharger le PDF** sur la page de
détail d'une procédure permet de choisir directement n'importe quel modèle de procédure publié et
actif, ou de le laisser sur celui actuellement marqué **Par défaut** dans Admin → Modèles →
Procédures (voir [Gérer les modèles](#gérer-les-modèles-base-par-défaut-et-actif) ci-dessus).

### Attribuer un modèle par défaut à une voie

Le reste de cette section (attribution au niveau voie/calibration) ne s'applique qu'aux modèles
de type **Certificat de Calibration**.

Ouvrez l'éditeur d'une voie de capteur (**Actifs → un actif → Aperçu → Modifier**) et définissez
**Modèle de rapport par défaut** sur n'importe quel modèle publié et actif, de l'un ou l'autre
type (téléversé en `.tex` ou créé dans l'éditeur). Chaque calibration enregistrée sur cette voie
l'utilise sauf remplacement individuel (ci-dessous). Laissez-le non défini pour se rabattre sur le
défaut de l'organisation, puis sur le modèle marqué **Par défaut** dans Admin → Modèles → Rapports
de Calibration (le modèle de base, si aucun autre n'est marqué).

### Remplacer le modèle pour une calibration

Sur la page de détail d'une calibration, le menu du chevron du bouton **Télécharger** permet à un
utilisateur ayant les droits de modification (tout rôle au-dessus de Visualiseur) de choisir un
modèle spécifique pour cette seule calibration — ce choix est **persisté**, pas un rendu
ponctuel : il devient ce que *tous* les utilisateurs téléchargent pour cette calibration à
l'avenir, jusqu'à être changé à nouveau ou effacé en revenant à "Modèle par défaut". Un
Visualiseur ne voit jamais ce menu — il obtient toujours le modèle résolu par le remplacement, le
défaut de la voie, ou le repli organisation/global, sans choix propre.
