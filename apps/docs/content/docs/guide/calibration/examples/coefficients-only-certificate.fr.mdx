Exerce le parcours de l'assistant
[Modèle (fonction de transfert)](../coefficients-only.mdx#model-transfer-function) — pour les
capteurs qui arrivent avec un certificat de calibration indiquant directement le modèle de
calibration, sans points de données référence/mesuré bruts à réajuster.

## 4.0 Configuration

**Actif** (Actifs → Nouvel actif) :

| Champ | Valeur |
|---|---|
| Nom | External Pressure Transmitter |
| Fabricant / Modèle | n'importe lequel, par ex. WIKA / A-10 |
| Type d'actif | capteur |

Une voie :

| Champ | Valeur |
|---|---|
| Identifiant de voie | CH1 |
| Grandeur physique | Pression |
| Plage min / max | 0 / 1000 |
| Unité | kPa |
| Exactitude | ±0,5 kPa (absolue) |

La spécification d'exactitude est ce à quoi la vérification de conformité du modèle fourni
directement est comparée — voir ci-dessous.

## 4.1 Assistant — Étape 1 (Informations générales)

| Champ | Valeur |
|---|---|
| Type de calibration | Laboratoire externe accrédité |
| Fournisseur de calibration | Any Cal Lab Inc. |
| Numéro de certificat | ACL-2026-00842 |

## 4.2 Assistant — Étape 2 (Données d'entrée)

L'étape 2 s'ouvre sur un sélecteur de méthode. Choisir **Modèle (fonction de transfert)** remplace
le reste de l'étape par un formulaire de saisie de modèle au lieu de la saisie de données brutes.

Le certificat indique : *référence ≈ 1,0025 × mesuré − 0,42 kPa, valide 0–1000 kPa, incertitude
élargie de l'étalon de référence ±0,5 kPa (k=2)*.

| Champ | Valeur |
|---|---|
| Type de modèle | Polynôme |
| Degré du polynôme | 1 |
| Coefficient (× x) | 1,0025 |
| Coefficient (Constante) | −0,42 |
| Plage valide min. | 0 |
| Plage valide max. | 1000 |

L'aperçu de l'équation affiche : $f(x) = 1.0025x - 0.42\ \text{(kPa)}$.

## 4.3 Assistant — Étape 3 (Vérification) et ce qui est enregistré

Même sans données brutes, l'étape 3 recueille les mêmes entrées de
[budget d'incertitude](../uncertainty-budget.mdx) qu'une calibration à données brutes :

| Champ | Valeur |
|---|---|
| U de l'étalon de réf. (manuel) | 0,5 |
| k de l'étalon de réf. | 2 |
| Règle de décision | Acceptation en bande de garde |

En coulisses, l'assistant évalue deux points synthétiques d'erreur nulle à la plage valide
déclarée (0 et 1000 kPa) via le même pipeline d'analyse que celui utilisé pour les données brutes,
l'ajustement étant ignoré — cela combine le budget de Type B ci-dessus (ici, uniquement le terme de
l'étalon de référence) et applique la règle de décision avec le modèle considéré comme fiable
exactement tel que déclaré. Lors de l'enregistrement :

- `poly_order = 1`, `poly_coefficients = [1.0025, -0.42]`, `range_min = 0`, `range_max = 1000`,
  `valid_range_min = 0`, `valid_range_max = 1000`.
- `uncertainty_budget` comporte une ligne de Type B (`reference_standard`, incertitude-type
  `0.5 / 2 = 0.25` kPa) — la ligne de Type A (`fit_residuals`) est présente mais vaut exactement
  `0`, puisque le modèle est considéré comme fiable tel que déclaré.
- `combined_uncertainty ≈ 0.25` kPa, `expanded_uncertainty ≈ 0.49` kPa (k≈1,96 à 95 % de
  confiance, distribution normale).
- `r_squared`, `rmse`, `max_error`, et `non_linearity` sont tous **null** — il n'y a pas de
  véritables données mesurées à partir desquelles les dériver (voir
  [Modes alternatifs de saisie des données de calibration](../coefficients-only.mdx)).
- `decision_rule = "guard_band_w_uncertainty"` et une véritable `conformity_statement` : la zone
  d'acceptation est réduite vers l'intérieur par l'incertitude élargie (`0.5 - 0.49 ≈ 0.01` kPa de
  marge restante), donc cet enregistrement **est CONFORME** — de justesse, illustrant exactement à
  quoi sert la bande de garde.
