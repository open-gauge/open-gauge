Ein **Verfahren** ist eine wiederverwendbare Kalibrierverfahrensvorlage, die einer physikalischen
Größe zugeordnet ist (z. B. ein dokumentierter Prozess zur Kalibrierung von Temperatur-RTDs gegen
ein Trockenblock-Referenznormal). Verwalten Sie sie über die Seite **Verfahren** in der Seitenleiste.

## Warum Verfahren existieren

ISO/IEC 17025 verlangt, dass ein Labor definierte Verfahren für seine Kalibrierarbeit dokumentiert
und befolgt. Die Verfahrensvorlagen von Open Gauge erfassen diese Dokumentation einmalig und lassen Sie
sie von jeder auf dieselbe Weise durchgeführten Kalibrierung aus referenzieren, statt Methodiknotizen
jedes Mal neu einzutippen.

## Felder

| Feld | Zweck |
|---|---|
| Name & physikalische Größe | Was dieses Verfahren kalibriert und für welche Größe. |
| Version | Freitext-Versionsangabe (z. B. `"1.0"`) — erhöhen Sie sie, wenn sich die Methodik ändert. |
| Schwierigkeitsgrad | Informativer Hinweis zum Kenntnisstand für denjenigen, der es durchführt. |
| Normreferenz | Freitext-Verweis auf eine externe Norm (eine ISO-/ASTM-Nummer usw.). |
| Autor, Dauer | Wer es verfasst hat und wie lange die Durchführung ungefähr dauert. |
| Schlagworte | Freie Bezeichnungen zur Suche/Filterung. |
| Ausrüstung | Strukturierte Liste der benötigten Ausrüstung. |
| Materialien | Strukturierte Liste der benötigten Materialien/Verbrauchsmittel. |
| Umgebung | Erforderliche Umgebungsbedingungen (Temperatur, Feuchte usw.), unter denen das Verfahren durchzuführen ist. |
| Sicherheitshinweise | Freitextliste der Sicherheitsaspekte. |
| Schritte | Die geordneten Verfahrensschritte selbst. |
| Abnahmekriterien | Was für dieses Verfahren als bestanden gilt, direkt daneben dokumentiert. |

## Ein Verfahren mit einem Kanal verknüpfen

Legen Sie bei einem Sensorkanal die **Kalibriermethode** auf ein gespeichertes Verfahren fest — dies
wird zum *Standard*-Verfahren des Kanals, vorausgewählt, sobald Sie eine neue interne Kalibrierung
für diesen Kanal starten. Es ist nur ein Standard: Jede Kalibrierung kann bei Bedarf ein anderes
Verfahren (oder keines) referenzieren.

## Wo Verfahren in einer Kalibrierung erscheinen

Eine **interne** Kalibrierung (siehe [Kalibrierübersicht](../calibration/overview.mdx)) kann das
befolgte Verfahren referenzieren (`internal_procedure_id`), und diese Referenz wird auf dem
resultierenden Zertifikat zusammen mit dem verwendeten Referenznormal und den erfassten
Umgebungsbedingungen ausgedruckt — die vollständige Rückführbarkeitskette, die ein
Kalibrierzertifikat benötigt.

## Import & Export

Nur für **Admin**- und **Superadmin**-Benutzer verfügbar. Jedes Verfahren kann als ZIP-Paket
exportiert werden — über die Schaltfläche **Exportieren** neben **+ Neues Verfahren** auf der
Verfahren-Seite, um eine Auswahl im Bulk zu exportieren (ein Auswahldialog lässt Sie einzelne
Verfahren auswählen oder alle auf einmal), oder über **+ Neues Verfahren → Aus Datei
importieren** für ein einzelnes Verfahren. Ein Bulk-Export besteht einfach aus mehreren
Einzelverfahren-Paketen innerhalb eines äußeren ZIPs und kann daher genauso wieder importiert
werden, wie er exportiert wurde.

Jedes Verfahren erhält einen eigenen Ordner, benannt nach seiner `proc_id` (z. B.
`PROC-TEMP-001/`), der Folgendes enthält:

- **`procedure.yaml`** — alle Verfahrensfelder (Name, Version, Schwierigkeitsgrad,
  Normreferenz, Tags, Ausrüstung, Materialien, Umgebung, Sicherheitshinweise, Schritte und
  Abnahmekriterien) in einem menschenlesbaren Format.
- **`media/steps/{n}/`** — die tatsächlichen Bytes jeder an Schritt `n` angehängten Datei
  (Bilder, PDFs usw.), ein Unterordner pro Schrittindex.

**Was absichtlich aus `procedure.yaml` weggelassen wird**: interne Datenbank-UUIDs — die eigene
ID des Verfahrens, `created_by` und die ID jeder Datei. Diese ergeben nur innerhalb der
Datenbank Sinn, aus der sie stammen.

### Importieren

Importieren Sie ein ZIP entweder über **Verfahren → + Neues Verfahren → Aus Datei importieren**
(erwartet genau ein Verfahren in der Datei) oder über die Schaltfläche **Importieren** der Seite
(akzeptiert ein oder mehrere ZIPs auf einmal, von denen jedes selbst einen oder mehrere
Verfahrensordner enthalten kann — praktisch zum erneuten Importieren eines vorherigen
Bulk-Exports). Beide Abläufe rufen denselben Backend-Endpunkt auf und melden ein Ergebnis pro
Verfahrensordner, sodass ein Problem mit einem Verfahren nie die anderen in derselben Datei
blockiert.

Beim Import wird ein völlig neues Verfahren mit einer neuen internen ID erstellt. Wenn die
exportierte `proc_id` im Zielsystem bereits existiert, schlägt der Import dieses Verfahrens mit
einer klaren Fehlermeldung fehl — benennen Sie es im YAML um und versuchen Sie es erneut.
